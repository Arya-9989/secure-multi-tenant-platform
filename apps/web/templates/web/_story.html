Every label mirrors the code it names: TenantJWTAuthentication.get_user, HasRolePermission, TenantQuerySet.visible_to and DRF's get_object, as exercised by test_unknown_and_foreign_ids_are_indistinguishable.{% endcomment %}

  1. 01Request

    Alice asks for Grace.

    Acme’s admin sends GET /api/v1/users/{id}/ with a valid token and the ID of a Globex user. The ID is real: Grace’s row sits in the same table as Alice’s.

    In the codeUserViewSet

  2. 02Tenant resolve

    The tenant comes from the database.

    TenantJWTAuthentication checks the signature, audience and issuer, then loads Alice’s row and her organization. A revoked token or an inactive tenant ends the request here with 401. Role and tenant are never read from token claims.

    In the codeTenantJWTAuthentication.get_user

  3. 03Scoped query

    Only Acme’s rows exist.

    HasRolePermission confirms her role may view users. Then every lookup runs through visible_to(alice), which adds Acme’s ID to the WHERE clause. Grace’s ID is looked up inside that filter, and the database returns zero rows.

    In the codeTenantQuerySet.visible_to

  4. 04404

    Not forbidden. Absent.

    With no row to return, the view answers 404 with the same body a random UUID gets, so the response confirms nothing. TenantObjectPermission stands behind it and also answers 404, should a view ever skip the scoping.

    Proven bytest_unknown_and_foreign_ids_are_indistinguishable
