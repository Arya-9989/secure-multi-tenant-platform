Isolation

Every request takes the same path.

TenantScopedViewSet assembles the layers, so no view can forget one. Rows from another tenant are filtered out before a handler ever sees them.

Guarantees

Five promises. Each one attacked by a test.

Shared database, shared schema, an organization key on every tenant-owned row. The isolation lives in code, so the code path is centralised and the tests are adversarial.

01

No cross-tenant reads.

A tenant user never receives another organization’s rows: not through detail routes, list routes, filters such as ?organization=, or search.

Proven bytest_cross_tenant_object_access_is_deniedtest_list_endpoints_never_return_foreign_rows

02

No cross-tenant writes.

Mutations on a foreign object fail before any state changes, and the test compares the row before and after to prove it is untouched.

Proven bytest_cross_tenant_object_access_is_denied

03

No existence oracle.

A foreign ID gets the same 404 as a random UUID. A foreign ID in a request body gets the same “does not exist” error.

Proven bytest_unknown_and_foreign_ids_are_indistinguishable

04

No escalation over HTTP.

SUPER_ADMIN can’t be assigned through the API and membership is immutable. Unknown or read-only fields are rejected with 400, never silently ignored.

Proven bytest_privilege_escalation.py

05

Fail-closed by construction.

Anonymous, inactive or org-less callers see nothing. Undeclared actions are denied. A view whose queryset isn’t tenant-aware raises ImproperlyConfigured.

Proven bytest_scoping_fails_closed_for_anonymous_and_orgless_users

And one more

A new endpoint can’t ship unprotected.

Structural tests fail the build if an API route is missing from the isolation suite, a routed viewset doesn’t subclass TenantScopedViewSet, or an action declares no permission.

Proven bytest_every_api_route_is_coveredtest_every_routed_viewset_is_tenant_scoped_and_declares_permissions

Roles

Three roles. One table.

Views declare the permission each action needs. The table decides which roles hold it. Anything undeclared is denied.

Rows stay inside the caller’s organization. Only super admins see across tenants.

Guard rails for every role: nobody can change their own role or status, super admin accounts can’t be managed over HTTP, and every organization keeps at least one active admin.

Sessions

Sessions you can actually end.

JWTs stay stateless for signature and expiry. One indexed lookup per request makes revocation immediate, and role and tenant always come from the database, never from token claims.

{{ access_ttl.value }}{{ access_ttl.unit }}

Access token lifetime. Audience and issuer are verified on every request.

{{ refresh_ttl.value }}{{ refresh_ttl.unit }}

Refresh token lifetime. Each refresh rotates the token and blacklists the old one.

{{ invitation_ttl.value }}{{ invitation_ttl.unit }}

Invitation expiry. Tokens are single-use, and only a SHA-256 digest is stored.

{{ auth_rate.value }}{{ auth_rate.unit }}

Per-client limit on every sign-in, API or admin, and on refresh, password change and invitation acceptance.

One integer revokes everything.

Logging out everywhere, changing a password or being deactivated bumps the user’s token_version. Every access and refresh token issued before it fails on the very next request. Deactivating an organization does the same for all of its members, so reactivating it later doesn’t revive old sessions. {% if password_min_length %}Passwords need at least {{ password_min_length }} characters.{% endif %}

Audit

A history nobody can rewrite.

Who, what, which tenant, IP, user agent and request ID, written in the same transaction as the change. The log never records something that rolled back.

Layer 1 · Model

Saves only once.

AuditLog.save() refuses to update an existing row, and delete() always raises.

Layer 2 · QuerySet

No bulk escape hatch.

update(), delete() and bulk_update() raise AuditLogImmutableError.

Layer 3 · PostgreSQL

The database says no.

A BEFORE UPDATE OR DELETE trigger rejects raw SQL too. Actors with history can’t be hard-deleted.
